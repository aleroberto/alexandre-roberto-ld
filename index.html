03 / PROVAS DE CASOS REAIS

Problemas que já encontrei. Soluções que coloquei em prática.

Se você chegou até aqui com um desafio de dados, esta é a parte mais importante: exemplos de problemas de negócio que já precisei transformar em fluxos, controles e entregas utilizáveis.

01
ENGENHARIA DE DADOS · INTEGRAÇÃO

Arquivos precisavam chegar diariamente ao destino correto de cada cliente.

O PROBLEMA

Arquivos Parquet de Data Quality chegavam ao Amazon S3, mas cada cliente possuía um destino diferente no OCI. Uma falha de cadastro ou comunicação não podia interromper todas as demais entregas.

COMO RESOLVI

Estruturei a orquestração no Azure Data Factory, consulta de destino no Azure SQL, staging no Blob e entrega no OCI, com registro de exceções, retry e reprocessamento por data.

RESULTADO

Uma distribuição diária automatizada, rastreável e com caminho claro para investigar e retomar falhas sem bloquear todo o fluxo.

ADF · S3 · Azure SQL · Blob · OCI · Kubernetes Ler o caso completo ↗
02
DATA QUALITY · PROCESSAMENTO

Nem todo dado inválido deveria derrubar um arquivo inteiro.

O PROBLEMA

Arquivos podiam chegar com schema incorreto, registros inconsistentes ou dados válidos que ainda dependiam de outra entidade. Tratar tudo como a mesma falha geraria descarte e reprocessamento desnecessários.

COMO RESOLVI

Separei o tratamento em camadas: validação estrutural do arquivo, regras de qualidade por registro e controle de dependências, isolando erros e preservando o que podia continuar.

RESULTADO

Erros passaram a ter destinos e tratamentos diferentes, enquanto registros aproveitáveis continuavam no fluxo e pendências podiam ser reavaliadas posteriormente.

Parquet · Python · SQL · PySpark · S3 Ler o caso completo ↗
03
BI · ANALYTICS · INFORMAÇÃO GERENCIAL

Fontes diferentes precisavam virar um único fechamento confiável.

O PROBLEMA

O fechamento mensal dependia de Oracle, SQL Server, APIs e arquivos CSV/TXT, recebidos em ritmos diferentes, mas os indicadores precisavam estar prontos para apresentação no primeiro dia útil.

COMO RESOLVI

Usei consultas e transformações SQL para consolidar as fontes, organizei a camada analítica com granularidade e regras de negócio coerentes e preparei o consumo dos indicadores no Power BI.

RESULTADO

As informações operacionais e financeiras passaram a compor uma visão gerencial única, com recorte temporal e totais preparados para o fechamento mensal.

Oracle · SQL Server · APIs · SQL · Power BI Ler o caso completo ↗
04
DATA OPERATIONS · AUTOMAÇÃO

Uma falha no pipeline ainda dependia de alguém abrir o incidente manualmente.

O PROBLEMA

Quando uma execução no Step Functions falhava, a equipe ainda precisava identificar a exceção e registrar manualmente um chamado no BMC Helix para iniciar o atendimento.

COMO RESOLVI

Desenvolvi uma prova de conceito em Python que capturava o contexto da falha e utilizava a API REST do BMC Helix para criar automaticamente o incidente com informações úteis à investigação.

RESULTADO

A prova de conceito evoluiu para produção e automatizou uma etapa que antes exigia intervenção manual da equipe.

Python · API REST · Step Functions · BMC Helix Ler o caso completo ↗
