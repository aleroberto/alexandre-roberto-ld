ESTUDO DE CASO / SUSTENTAÇÃO / BATCH

Reprocessamento no ciclo de seguro garantia

Identificar apólices e endossos pendentes, preparar a intervenção de produção e submetê-los novamente ao ciclo batch.

Alexandre RobertoSetembro de 2026Shell · Python · SQL · Oracle · Helix · Spring Batch

01 / PROBLEMA

Problema

Apólices e endossos não eram integrados inicialmente por informações incompletas ou inconsistentes enviadas pelos clientes. Após a correção, era preciso selecionar o que deveria voltar ao fluxo.

02 / SELEÇÃO

Seleção

Uma rotina em Shell baixava arquivos D-1 do servidor. Python e SQL examinavam os status de integração e selecionavam os números de apólice elegíveis para reprocessamento.

03 / INTERVENÇÃO CONTROLADA

Intervenção controlada

O processo gerava um arquivo SQL para limpeza e carga de uma tabela de reprocessamento no Oracle. O arquivo seguia anexado a um chamado no Helix, para execução pelo suporte à produção dentro do SLA.

04 / EXECUÇÃO POSTERIOR

Execução posterior

Um processo noturno em Spring Batch realizava o reprocessamento. Selecionar um registro, gerar o SQL, aplicar a mudança e confirmar a integração são etapas diferentes, cada uma com seu controle.

05 / RESULTADO

Resultado

O fluxo criou um caminho controlado de retomada de registros, combinando automação e passagem formal para a operação. Não há métrica pública de volume ou sucesso final por execução.
